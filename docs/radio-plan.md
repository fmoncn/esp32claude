# 克劳德网络电台功能 — 实施计划

## 目标
让克劳德能播放网络低码率语音/音乐电台（新闻、有声书、音乐），像电子宠物一样有"背景声音"。

## 关键认知（来自社区参考项目 halbeshuhn/Cardputer-WebRadio）
在无 PSRAM 的 Cardputer ADV 上播放网络电台**可行**，但有硬约束：
1. **只能用 http://**（https 的 mbedTLS 需 32KB，无 PSRAM 内存不足 → 崩溃）
2. **只能用 MP3**（AAC 的 faad2 解码器 71 处 malloc，无 PSRAM 第一次紧分配就 NULL → 崩溃）
3. **码率 ≤128kbps**（输入缓冲仅 13,951 字节，128kbps 是甜点，256kbps 卡顿）
4. **播放时仅剩 13-25KB 空闲堆**（解码器+流缓冲占满内部 RAM）
5. **I2S 引脚 41/43/42**（与克劳德一致）
6. **库补丁**：拒绝无 PSRAM 时的 https（防 mbedTLS 耗尽内存）

## 硬件引脚（已确认）
- **I2S 音频输出**：BCK=41, WS=43, DOUT=42（ESP32-audioI2S 用这个，与克劳德一致）
- **SD 卡（SPI 模式）**：CLK=40, MOSI=14, MISO=39, CS=12（来自 M5Unified `_pin_table_sd`）
  - 注意 SD 用 GPIO 40，I2S 用 41/43/42，无直接冲突，但需验证共用

## 技术方案
- 用 **ESP32-audioI2S** 库（schreibfaul1 v3.0.13），PSRAM Disabled 编译
- 电台列表存 SD 卡 `station_list.txt`（name,url 每行）
- 独立"电台模式"（如 Fn+R 切换），不干扰克劳德现有功能
- 音频输出走 M5 Speaker / 底层 I2S（需复用之前验证的技术）

## 内存风险评估
克劳德 vs 电台项目的差异：
- 克劳德：88KB 静态 + 场景渲染/精灵/STT/对话/抚摸/主动对话（运行时功能多）
- WebRadio 专用：精简，仅电台，播放时剩 13-25KB
- **风险**：克劳德功能叠加电台播放，可能 OOM / 崩溃 / 卡顿

## 实施步骤（分阶段，先验证再集成）

### 阶段 0：预研确认（已完成）
- 确认 ESP32-audioI2S 在无 PSRAM 可编译 ✅
- 确认 I2S 引脚 41/43/42 匹配 ✅
- 确认 http MP3 电台可播 ✅

### 阶段 1：技术验证 Spike（已完成 ✅ 成功）
- ESP32-audioI2S v3.0.12 在无 PSRAM 下编译通过（RAM 25%，Flash 74.5%）
- **关键突破**：播放 SomaFM Drone Zone (http MP3 128kbps) 成功
- **DNS 修复**：设备默认 DNS 解析不了国外域名，改用公共 DNS (223.5.5.5/119.29.29.29) 解决
- **结果**：出声正常、无崩溃、内存稳定 ~120KB 空闲、曲目名获取正常
- **注意**：128kbps 无 PSRAM 下轻微卡顿（缓冲不足，可接受或优化）

### 阶段 2：SD 卡初始化
- 启用 SD 卡（查 Cardputer 引脚）
- 读 `station_list.txt`
- 验证 SD 卡读取

### 阶段 3：电台模式集成
- 新增"电台模式"（Fn+R 或 BtnG0 菜单）
- 电台列表 UI（上下选台、音量、静音、重连）
- 不干扰克劳德场景/对话/STT

### 阶段 4：内存优化
- 播放时动态释放不需要的缓冲（如场景精灵）
- 监控 heap，避免 OOM
- 若内存不足：考虑播放时暂停克劳德部分功能

### 阶段 5：打磨
- 电台名/曲目显示（audio_showstreamtitle 回调 → 主循环显示）
- 音量控制、静音、重连
- 优雅退出电台模式回克劳德

## 关键决策点
1. **播放时暂停克劳德动画/场景**（方案 A，用户已确认）：播放电台时只留电台 UI，不跑场景/精灵/动画/对话，最省内存
2. **电台模式入口**：待定（Fn 快捷键 vs 菜单），倾向 Fn 快捷键快速切换
3. **接受播放时仅剩 13-25KB**：是，方案 A 已最大限度省内存

## 风险与缓解
- **OOM/崩溃**：分阶段验证，内存监控，动态释放
- **刺耳/音频损坏**：复用之前验证的 I2S 方案，Spike 先行
- **SD 卡冲突**：先查清 Cardputer SD 引脚与现有 SPI 冲突
